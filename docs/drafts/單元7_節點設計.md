# 單元 7 節點設計（草稿，尚未在 Coze 建，沒有任何結果）

課綱檢核（`knowledge/ai_agent_course_syllabus.md` 單元 7）：流程截圖＋實際對話截圖；每輪抽出性別、職業、年紀、想上的課並填進變數；任一變數沒填妥，開一個 LLM 要求使用者補齊；四個都齊了，查 knowledge，把結果交給 LLM 回應。

## 為什麼和單元 6 不一樣

單元 6 每輪都是「從零抽取」，沒有記憶。單元 7 的新難題只有一個：**第 2 輪使用者只說「我 22 歲」時，第 1 輪抽到的性別、職業要還在**。所以核心是「記住＋合併」，不是抽取。

## 流程

```
Start
 → Get variable（讀出目前記住的 gender / occupation / age / course）
 → LLM「抽取」（輸入：本輪使用者話；輸出：本輪抽到的四欄，沒提到就空字串）   ← 沿用單元 6
 → Code「合併」（本輪非空才覆蓋舊值，否則保留舊值；輸出：合併後四欄＋缺哪些）
 → Set variable（把合併後四欄寫回）
 → Condition（缺的欄位清單是否為空？）
      ├ 有缺 → LLM「追問」（輸入：缺哪些、已知哪些；一次只問一件事）→ Output → End
      └ 齊了 → Knowledge retrieval（查詢字串＝course）→ LLM「回應」（只依檢索結果回答）→ Output → End
```

## 設計取捨（我的推理，待你同意）

1. **合併用 Code 節點，不用 LLM。**「非空才覆蓋」是固定規則，寫成程式不會漏。若讓 LLM 合併，它可能把舊值弄丟，而且我會看不出是哪一步壞。這延續單元 6 的方向：公式歸程式、語意歸 LLM。代價：Code 節點我還沒在這個 Coze 版本用過，要先確認能用（【待試】）。備案：把已知值一起餵給抽取 LLM 讓它輸出合併結果，但可靠性較低。
2. **「記憶」用 Coze 的變數（Set/Get variable）。**單元 3 遇過變數寫入不穩，所以第一步先單獨測「第 1 輪寫入、第 2 輪讀得到」，不通過就不往下建。
3. **追問每次只問一件事。**一次問四件事使用者容易漏答，之後合併也更難驗。
4. **回應 LLM 的 prompt 限定「只依檢索結果」**，檢索不到就說查不到，不要自己編課程。
